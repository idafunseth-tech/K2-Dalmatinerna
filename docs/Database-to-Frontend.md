### Traceability Table: Database - Frontend

| User Need | Database Support | Frontend Support | Acceptance Criteria |
| :--- | :--- | :--- | :--- |
| **1. Book an activity & see updated count**<br>As a user, I want to book an activity and immediately see the updated number of available slots. | **Stored Procedure:** `[dbo].[usp_CreateBooking]`<br>• Executes an `INSERT` into `dbo.Booking`.<br>• Returns a result set (`ActivityID`, `ActivityName`, `TotalQuantity`) for the selected activity. | **Component & State Management:**<br>• Sends `PersonID` and `ActivityID` on button click.<br>• Receives the returned dataset and updates the slot counter on screen without reloading the page. | • A new record is created in `dbo.Booking`.<br>• The UI component immediately displays the updated slot count after completion. |
| **2. Robust error handling for invalid input**<br>As a user, I want a clear message if a booking cannot be completed, without the application crashing. | **Validation & Safe Exit:**<br>• Checks if `PersonID` and `ActivityID` exist.<br>• Returns an empty structure (`WHERE 1 = 0`) if input is missing to prevent crashes in the ORM/data layer. | **Error & Message Handling:**<br>• Detects if the response is empty or contains an error code.<br>• Displays a user-friendly error message (e.g., *"The selected activity or user could not be found"*). | • No unhandled database exceptions crash the application on invalid IDs.<br>• A helpful error message is displayed to the user in the UI. |
